# VOXWEAVE Owner-Scoped Loopback Integration Evidence Plan v1.2.6

## Executive Summary

This plan defines the owner-scoped, local fake-only loopback integration
evidence lane for VOXWEAVE before any runtime integration claim is made. It
permits only ephemeral loopback execution with fake in-memory fixtures and safe
JSON summaries. It forbids external network execution, real providers, real
renderers, raw logs, raw payloads, secrets, tokens, private paths, and readiness
claims.

## Execution Scope

The planned evidence runner may use only local ephemeral loopback resources:

- VOXWEAVE server: 127.0.0.1 ephemeral port
- fake renderer: 127.0.0.1 ephemeral port
- server API key: in-memory fake fixture only
- renderer API key: in-memory fake fixture only
- external network: forbidden
- DNS: not required
- real provider: forbidden
- real renderer: forbidden
- raw logs: forbidden
- output: safe JSON summary only

The evidence runner must bind evidence to the current source head and must not
claim runtime readiness, production readiness, real TTS readiness, ASR
readiness, or Live2D renderer readiness.

## Happy-Path Evidence

The happy-path lane should prove only that local fake loopback boundaries are
wired as expected:

- public health path is reachable on loopback
- authenticated TTS route accepts a safe fixture
- authenticated subtitle route accepts a safe fixture
- authenticated Live2D route accepts a safe fixture
- all six AI character contracts are accepted by safe fixtures
- safe integration boundary snapshot is present
- fake renderer receives JSON cue material
- fake renderer receives fake authorization material
- forbidden raw material is absent from evidence output
- VOXWEAVE server and fake renderer cleanup pass

## Negative Evidence

The negative lane should cover bounded rejection behavior without widening into
product verification:

- unauthorized POST returns 401
- missing or non-JSON content type returns 415
- route mismatch returns 400
- unknown route returns 404
- unsafe contract is rejected before metadata output

## Failure Evidence

The failure lane should prove cleanup and safe classification for local fake
failures:

- fake renderer rejected
- fake renderer timeout
- local connection reset
- redirect blocked
- cleanup after every failure

Failure evidence must be summarized with safe classes only. It must not expose
raw stack traces, raw error messages, ports, URLs, endpoints, hosts, request
bodies, response bodies, or authorization material.
